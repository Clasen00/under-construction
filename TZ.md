# Тестовое задание

Репозиторий: https://github.com/thefubon/under-construction  
Эталон вёрстки: https://iva360.ru  
UI Kit (обязателен): https://uikit-iva360-react.vercel.app/ · [установка](https://uikit-iva360-react.vercel.app/installation)

В CMS есть пользователи и медиа. Нужно сделать схему, контент и вёрстку шапки, Hero и страницы тарифов.

---

## 1. Окружение

1. Клонировать репозиторий:

```bash
git clone https://github.com/thefubon/under-construction.git
cd under-construction
```

2. Нужны Node.js `^18.20.2` или `>=20.9.0`, pnpm `^9`/`^10`, Docker + Docker Compose, Git.

3. Развернуть локально (`.env`, зависимости, Docker: Mongo + MinIO, заливка дампов):

```bash
pnpm setup
pnpm dev
```

Эквивалент вручную: `cp .env.example .env` → `pnpm install` → `docker compose up -d` → `pnpm dev`.

Дампы ставятся сами при первом запуске Docker (пустой volume):

- Mongo: `backup/mongo/iva360.archive.gz` (если коллекция `users` пустая)
- MinIO: `backup/minio/data` → бакет `iva360-media` (если бакет пустой)

4. Адреса и доступы

| Сервис | URL |
| --- | --- |
| Сайт | http://localhost:3033 |
| Админка | http://localhost:3033/admin или http://localhost:3333/admin |

- CMS: `demo@example.ru` / `demo`
- MinIO console (http://127.0.0.1:9003): `minioadmin` / `minioadmin`

Сброс БД и повторный restore: `docker compose down -v && docker compose up -d`.

## 2. Обязательная часть

### 2.1. Шапка и Hero в CMS

Завести в Payload схему для шапки и главной.

Ожидается:

- глобал или коллекция **Шапки**: логотип, название, меню (в т.ч. подпункты), топбар, кнопки входа/регистрации;
- глобал или коллекция **Главной** с блоком **Hero**: текст, описание, картинка, CTA;
- контент в CMS, внешний вид и сетка — на фронте, не из админки;
- без произвольных цветов/CSS от редактора;
- оформление только пресетами (select), если без вариантов нельзя;
- после схемы: `pnpm generate:types`.

Цель схемы: контент-менеджер не должен ломать вёрстку свободными hex-цветами, произвольным размером заголовка или кастомным фоном кнопок.

### 2.2. Вывести шапку и Hero на сайт

Написать виджеты и подключить данные из CMS.

Нужно:

- подключить шапку в layout фронта;
- на главной рендерить Hero (и другие блоки главной, если заведёте);
- страница собирается из widgets, без бизнес-логики в `page.tsx`.

Клиент к Payload — в `apps/web/src/shared/api`. Главная: `apps/web/src/app/[locale]/(frontend)/page.tsx`.

### 2.3. Пиксель-пёрфект: шапка и Hero

Эталон: шапка и Hero на https://iva360.ru.

**Обязателен пиксель-пёрфект** шапки и Hero относительно прода: отступы, сетка, типографика, размеры, состояния (топбар, лого, пункты, кнопки входа). Допустимы отличия только там, где мешает UI Kit или нет исходных ассетов — это нужно явно указать при сдаче.

### 2.4. Мобильная вёрстка

Мобильная версия — такая же обязательная часть, как десктоп. Эталон: https://iva360.ru и https://iva360.ru/tariffs в узком вьюпорте (ориентир **375px**, плюс планшет по возможности).

Ожидается:

- шапка: топбар, бургер, выезжающее меню, подпункты, кнопки входа — как на проде, без обрезания и наложения;
- Hero и страница тарифов: своя сетка на мобилке (колонки складываются, отступы и кегль не «сжимаются» с десктопа);
- касаемые зоны, без горизонтального скролла страницы, без наложений текста и картинок;
- состояния hover не заменяют мобильное поведение (меню открывается тапом).

Пиксель-пёрфект шапки и Hero проверяется и на десктопе, и на мобилке.

### 2.5. Страница тарифов

**Обязательно** сверстать страницу тарифов. Эталон: https://iva360.ru/tariffs.

Ожидается:

- отдельный маршрут на сайте (не только блоки на главной);
- состав и визуал как на эталоне на десктопе и мобилке: секции, карточки/таблица тарифов, типографика, отступы;
- шапка та же, что на всём сайте;
- данные — из CMS или из структурированного источника; без корзины, модалок заказа и логики покупки;
- страница собирается из widgets, без бизнес-логики в `page.tsx`.

### 2.6. Наполнить админку

В CMS заполнить шапку, главную и страницу тарифов как на iva360.ru: логотип, меню, топбар, кнопки входа/регистрации, тексты и медиа Hero, контент страницы тарифов. Локали `ru` / `en` — по возможности.

### 2.7. Только UI Kit проекта

Только компоненты UI Kit проекта / shadcn `@iva360/*`. Ставить из `apps/web`:

```bash
cd apps/web
pnpm dlx shadcn@latest add @iva360/<name>
```

Импорт: `@/shared/ui/<name>`. Иконки: `@/shared/lib/icons` или Hugeicons. Полиморфизм Base UI: `render`, не `asChild`.

Запрещено: свой UI с нуля, Lucide как основная библиотека, `src/components/ui`, `packages/ui`, правка исходников UI Kit (токены, CVA, `data-slot`, compound-дерево). Недостающий компонент — ставить через CLI в `shared/ui`.

FSD: `app → widgets → features → entities → shared`. Фичи — в `widgets/` / `features/`, не копировать UI Kit в другие слои.

## 3. Как подходить к заданию

Оцениваются собственные знания, ручное написание кода, понимание того, что сделано, и продуктовое мышление: зачем поле в CMS, почему такая схема, как контент-менеджер будет этим пользоваться.

Нейросеть — помощник для рутины: деплой, сборка, проверка типов, поиск по доке, повторяющиеся правки. Не замена работе. Сгенерировать всё целиком и не уметь объяснить — недостаточный результат.

## 4. Сдача

- Репозиторий (fork/ветка) + инструкция, если шаги отличаются от `pnpm setup` / `pnpm dev`.
- Локально: **пиксель-пёрфект** шапка и Hero с данными CMS относительно https://iva360.ru — **десктоп и мобилка**.
- Сверстана страница тарифов по https://iva360.ru/tariffs (десктоп и мобилка).
- Админка заполнена.
- UI только из UI Kit проекта.

Критерий Hero: смена текстов/картинок/ссылок в CMS не ломает сетку и типографику на сайте.
